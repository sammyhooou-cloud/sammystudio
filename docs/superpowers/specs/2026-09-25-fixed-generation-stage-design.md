# 固定视频生成舞台与深黑磨砂登录界面设计

## 目标

在保留现有视频背景、项目结构和可灵生成能力的前提下，完成四项界面修正：

1. 登录第一屏恢复早期的深黑色磨砂玻璃质感，但不恢复实体手机外框。
2. 生成任务完成后，结果区域只显示已完成的视频片段，不再保留生成进度层。
3. 新任务生成期间，进度视觉固定在结果舞台正中；上一条已完成视频进入下方历史列表。
4. 消除进度动画随内容高度、历史列表或响应式布局发生漂移的问题。

## 选定方案

采用用户确认的 **A：固定结果舞台**。

结果面板拆分为两个稳定区域：

- `result-stage`：固定高度或受控最小高度的当前任务舞台。
- `completed-list`：位于舞台下方的已完成片段列表。

进度视图、空状态和当前视频是舞台内互斥的三种状态，不再依靠普通文档流混排。

## 登录第一屏

- 保留已授权的 MotionSites 循环视频背景和现有可读性遮罩。
- 登录框使用接近黑色的半透明渐变底色、高强度背景模糊、轻微饱和度和一像素高光边缘。
- 阴影保持深而柔和，输入框使用低透明度亮色内层，形成深黑磨砂玻璃质感。
- 登录框固定居中，不增加手机边框、刘海、实体按键或设备外壳。
- 移除会造成整体位置漂移的容器浮动动画；仅允许不改变布局位置的轻微视觉过渡。

## 任务状态与界面行为

### 无任务

- 舞台显示空状态提示。
- 进度视图和视频均隐藏。
- 历史区仅在存在已完成片段时显示。

### 提交中、排队或生成中

- 舞台显示固定居中的生成视图。
- 核心视觉为不改变元素位置的渐变动画。
- 当可灵结果没有可靠的真实百分比时，只显示“生成中”，不显示估算数字。
- 只有服务结果明确提供可信百分比字段时才显示 `n%`。
- 历史区继续显示此前已完成的视频片段，不因新任务开始而消失。

### 生成成功

- 进度视图立即隐藏并从可见布局中移除。
- 当前舞台只显示生成完成的视频。
- 状态文案显示“已完成”。
- 此视频同时成为历史列表的第一项；当后续新任务开始时，它只保留在下方历史列表。

### 失败或状态未知

- 舞台显示稳定的错误或待核对状态，不继续播放生成动画。
- 已完成片段历史仍保持可见。
- 不自动重复提交付费任务。

## 历史片段列表

- 下方列表只展示能够解析出安全视频地址的已完成任务。
- 每项显示片段序号、完成状态和可播放入口；不再把排队、失败或未知任务当作已完成片段。
- 点击历史片段会在当前舞台播放该视频，但不会重新显示进度层。
- 新任务开始后默认选择新任务；旧视频仍在列表中可随时查看。

## 固定与响应式规则

- 结果舞台使用 `position: relative`，内部状态层使用 `position: absolute; inset: 0` 或等价的固定网格覆盖方式。
- 生成视觉通过舞台自身的网格居中，不依赖外部内容高度、负边距或位移动画。
- 桌面端维持左右双栏；窄屏切换为单栏时舞台仍保持独立高度，历史区位于舞台下方。
- 动画仅改变渐变、透明度或旋转角度，不修改元素的 `top`、`left` 或会影响布局的位移。
- `prefers-reduced-motion` 下停用循环动画，保留静态生成状态。

## 状态数据与安全边界

- 继续使用现有项目级任务隔离和轮询机制。
- 新增纯函数将任务列表归类为：当前活动任务、当前可播放结果、已完成片段历史。
- 视频地址继续通过现有安全解析逻辑过滤，不接受不安全协议。
- 不修改登录凭据、可灵 OAuth、项目数据模型、存储结构或站点公开访问设置。

## 测试与验收

先写失败测试，再实现最小修复：

- 活动任务时进度视图可见、视频不可见。
- 成功任务时进度视图隐藏、视频可见。
- 新任务开始时，上一次成功视频进入完成列表。
- 完成列表只包含成功且具有可播放地址的任务。
- 无真实百分比时不渲染虚假数字。
- CSS 保证结果舞台为稳定定位上下文，生成层固定居中，动画不含布局位移。
- 登录框满足深黑磨砂样式，且不包含实体手机外框和漂浮动画。
- 全量自动测试和生产构建通过后再发布。

## 不在本次范围

- 不改变可灵生成参数、计费行为或 MCP/OAuth 连接方式。
- 不新增真实进度接口；未来若可灵返回可信百分比，可直接接入现有显示槽位。
- 不重构项目导航、图片上传或账户余额功能。
