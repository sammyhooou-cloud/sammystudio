# MiniMax / 可灵双视频供应商与 GitHub CI 设计

日期：2026-09-29

状态：已完成方案讨论，等待书面规格审核

## 1. 目标

在现有视频生成工作台中加入 MiniMax，使用户能在同一个项目内选择可灵或 MiniMax，并继续使用现有的任务创建、进度展示、历史列表与结果详情流程。

本次同时增加 GitHub 持续集成检查。CI 只验证代码，不自动部署，也不读取生产密钥。

## 2. 已确认的产品决定

- 供应商选择保存到一级项目；重新进入项目时恢复上次选择。
- 每个视频任务永久记录实际供应商，切换项目供应商不会改变历史任务。
- MiniMax 第一版支持：
  - 文生视频。
  - 单张首帧图生视频。
- 工作台顶部只显示当前所选供应商的连接状态。
- MiniMax 不展示无法可靠获取的数字余额；状态区域显示“额度：控制台查看”。收到明确的余额不足响应时再显示“额度不足”。
- MiniMax 图生视频的画幅由参考图决定，界面显示“跟随参考图”，不提供会被服务端忽略的画幅选择。
- MiniMax 生成成功后立即把成片复制到本站 R2 存储，结果页不依赖有时效的供应商下载地址。
- GitHub CI 在拉取请求以及推送到 `main` 时运行检查，不做自动部署。

## 3. 范围

### 包含

- 统一的视频供应商接口。
- 将现有可灵调用接入该接口，保持现有行为。
- MiniMax 任务创建、查询、状态归一化和成片持久化。
- 项目级供应商设置。
- 创建表单根据供应商和模式显示有效参数。
- 顶部供应商状态、任务卡片和结果详情中的供应商标识。
- MiniMax 的服务端密钥配置与安全处理。
- GitHub Actions 检查工作流。
- 数据库迁移、单元测试和端到端关键路径回归。

### 不包含

- MiniMax 数字余额查询或充值功能。
- 多图、尾帧、主体参考、音频或高级镜头控制。
- 在浏览器中保存或传输 MiniMax API Key。
- 自动部署到生产环境。
- 修改现有登录、项目层级、背景或无关视觉功能。

## 4. 总体架构

新增一个服务端供应商适配层，业务路由和任务状态机只依赖统一接口，不直接依赖某家供应商的字段。

统一接口的职责：

- `getCapabilities()`：返回支持的模式、模型、时长、分辨率与画幅规则。
- `checkConnection()`：返回当前供应商的可用状态和适合展示的说明。
- `createTask(input)`：创建远端任务，并返回供应商任务 ID 与归一化初始状态。
- `queryTask(providerTaskId)`：查询远端任务，返回归一化状态、错误和临时结果地址。
- `normalizeError(error)`：把供应商错误转换成稳定的站内错误码与用户文案。

现有可灵逻辑被一个 Kling 适配器包裹；OAuth、MCP 状态和余额行为不改。MiniMax 使用独立适配器，通过官方 HTTP API 工作。路由按任务记录的 `provider` 查找适配器，因此历史任务不会受到项目当前选择变化的影响。

供应商适配器不负责页面渲染、数据库写入或 R2 上传。这些仍由任务服务统一编排，避免两套流程逐渐分叉。

## 5. 配置与安全

- MiniMax 密钥只存在于服务端 Secret：`MINIMAX_API_KEY`。
- 密钥不得写入 Git、前端资源、数据库、日志、错误响应或分析事件。
- 密钥缺失时，MiniMax 状态显示“未配置”，创建按钮禁用；可灵仍可正常使用。
- MiniMax 请求设置明确的连接与响应超时，并对响应体做长度受控的安全解析。
- 日志只记录供应商、站内任务 ID、远端任务 ID、HTTP 状态和归一化错误码。
- 用户此前在聊天中暴露且已撤销的密钥不会被使用；上线前必须在托管平台的 Secret 设置中录入一枚新密钥。

## 6. 数据模型

### 项目

在 `projects` 增加：

- `video_provider TEXT NOT NULL DEFAULT 'kling'`

允许值由应用层限制为 `kling` 或 `minimax`。旧项目迁移后默认使用可灵，避免行为变化。

### 视频任务

在 `video_tasks` 增加：

- `provider TEXT NOT NULL DEFAULT 'kling'`

`provider` 在任务创建时从项目设置复制，此后不可变。现有 `remote_id` 保存对应供应商的远端任务 ID，供轮询和故障恢复使用；模型和生成参数继续保存在现有 `request_json` 中，不重复增加字段。

### 任务输出

新增 `task_outputs` 表，用于成片，不与用户上传的参考素材混用：

- `id`
- `task_id`
- `object_key`
- `content_type`
- `byte_size`
- `created_at`

每个第一版视频任务最多有一个主视频输出。`task_id` 唯一约束防止轮询重入时重复复制和重复记录。

## 7. MiniMax API 映射

依据 MiniMax 官方视频 API：

- 创建：`POST https://api.minimax.io/v2/video_generation`
- 查询：`GET https://api.minimax.io/v2/query/video_generation/{task_id}`
- 文生视频只发送文本提示词与用户选择的受支持参数。
- 图生视频把已上传参考图读取为 Base64 data URI，并以 `image_url`、`role: first_frame` 发送；不生成公开参考图 URL。

第一版模型选项：

- `MiniMax-H3`：768P 或 2K，4–15 秒。
- `MiniMax-H3-Max`：480P 或 768P，5–15 秒。

前端选项由服务端能力数据生成或校验，不能只依赖浏览器限制。若官方约束变化，服务端拒绝无效组合并返回可执行的中文提示。

## 8. 状态与任务流程

站内状态继续使用现有集合：

- `submitting`
- `queued`
- `generating`
- `succeeded`
- `failed`
- `unknown`（创建结果不明确，需要人工核对）

流程：

1. 浏览器提交站内任务。
2. 服务端验证登录、项目权限、供应商、模式、模型、参数及参考图归属。
3. 服务端先建立唯一的站内任务记录，再发起一次供应商创建请求。
4. 成功取得远端任务 ID 后写回任务。
5. 页面按现有节奏轮询站内任务；服务端查询对应供应商并归一化状态。
6. 供应商成功时，服务端只执行一次结果固化：下载临时视频、验证类型和大小、写入 R2、建立 `task_outputs` 记录，然后标记站内任务成功。
7. 结果页通过现有鉴权链路读取 R2 成片。

### 防止重复扣费

- 创建操作继续使用现有幂等键或等价的唯一提交保护。
- 已有 `remote_id` 的任务绝不再次调用创建接口。
- 创建请求若明确失败，可安全标记失败。
- 创建请求若超时或响应不明确，不自动重试付费调用；任务进入 `unknown`，向用户显示需要人工核对的明确说明。
- 查询请求和结果下载可按受控退避重试，因为它们不创建新的付费任务。

## 9. 页面设计

### 创建区

在“文生视频 / 图生视频”切换上方加入供应商切换：`可灵`、`MiniMax`。

- 切换后立即保存到当前一级项目。
- 切换时重建有效的模型、分辨率、时长和画幅选项。
- 不保留对新供应商无效的旧选项；使用该供应商的默认有效值。
- 可灵界面与现有参数保持一致。
- MiniMax 文生视频显示模型、分辨率、时长和画幅。
- MiniMax 图生视频显示单张参考图、模型、分辨率、时长；画幅位置显示不可编辑的“跟随参考图”。
- 上传后的文件名、大小、成功状态与自适应预览继续显示。

### 顶部状态

只显示当前供应商：

- 可灵：沿用 MCP 连接、会员与余额信息。
- MiniMax：显示 API 在线/未配置/异常；额度显示“控制台查看”，明确 402 时显示“额度不足”。

切换供应商时状态区域显示短暂加载态，旧供应商状态不得残留。

### 进度、历史和结果

- 运行中仍使用居中的固定渐变“生成中”展示；没有真实百分比时不伪造百分比。
- 任务卡片增加 `可灵` 或 `MiniMax` 标签。
- 完成后运行中卡片被完成结果替换，旧完成视频继续位于下方历史列表。
- 结果详情显示供应商、模型、参数、提示词和站内视频播放器。
- 成片未完成 R2 固化前不得提前显示“完成”。

## 10. 错误处理

对用户显示稳定、可操作的中文错误，不直接暴露供应商原始响应：

- `provider_not_configured`：MiniMax 尚未配置，请管理员添加服务端密钥。
- `provider_unavailable`：供应商暂时不可用，请稍后重试。
- `invalid_parameters`：当前模型不支持所选分辨率或时长。
- `insufficient_balance`：供应商账户额度不足。
- `reference_image_invalid`：参考图缺失、无法读取或格式不支持。
- `submission_uncertain`：创建响应不明确，为避免重复扣费已停止自动重试。
- `output_persist_failed`：视频已生成，但保存到本站失败；任务保留远端信息供安全恢复。

认证失败和 402 不重试。429、5xx、网络中断仅对查询和下载使用指数退避；创建调用遵循防重复扣费规则。

## 11. GitHub CI

新增 `.github/workflows/ci.yml`：

- 触发：`pull_request`；推送到 `main`。
- 环境：Ubuntu、Node.js 22。
- 步骤：检出代码、执行 `npm test`、执行 `npm run build`、执行 `git diff --check`。
- 不部署、不调用供应商、不使用生产 Secret。
- 测试中的 MiniMax HTTP 请求全部 mock，严禁在 CI 产生付费任务。

仓库当前跟踪 `dist` 构建产物，因此 CI 在构建后执行 `git diff --exit-code -- dist`；有差异即失败，确保提交产物与源码一致。

## 12. 测试策略

### 单元测试

- 项目供应商读取、保存、默认值和非法值拒绝。
- 两个适配器的能力、创建输入、状态映射和错误映射。
- MiniMax 文生与首帧图生请求体。
- 模型、分辨率、时长组合校验。
- 密钥缺失、401、402、429、5xx、超时及畸形响应。
- 已有远端任务 ID 时不会再次创建。
- 结果固化的唯一性与失败恢复。

### 路由与界面测试

- 切换项目恢复各自供应商。
- 切换供应商后参数列表和顶部状态同步更新。
- MiniMax 图生画幅显示“跟随参考图”。
- 任务卡片和结果详情显示正确供应商。
- 无真实百分比时只显示渐变“生成中”。
- MiniMax 未配置时仅禁用 MiniMax 创建，可灵不受影响。

### 回归

- 现有可灵 OAuth、MCP 状态、余额、文生、图生、任务历史、结果详情与项目功能全部保持可用。
- 登录独立页和移动端布局不得退化。

真实 MiniMax 冒烟测试只在部署后由管理员使用新密钥手动执行一次，不进入自动测试。

## 13. 验收标准

- 用户可在一级项目中选择可灵或 MiniMax，刷新或重新登录后选择仍保留。
- 两个项目可保存不同供应商。
- MiniMax 可完成一次文生视频和一次单首帧图生视频。
- MiniMax 任务状态、完成历史和结果详情与可灵保持一致的交互结构。
- MiniMax 成片由本站 R2 提供，即使供应商临时下载地址过期仍可播放。
- 任何浏览器资源、仓库文件、数据库记录和普通日志中都没有 MiniMax API Key。
- 不明确的创建响应不会自动发起第二次付费请求。
- 可灵现有真实生成流程无回归。
- GitHub 拉取请求和 `main` 推送会自动运行测试、构建与格式差异检查，且不会部署。

## 14. 上线顺序

1. 合并数据库迁移和适配层，但默认仍为可灵。
2. 在托管环境录入新 `MINIMAX_API_KEY`。
3. 部署并验证 MiniMax 连接状态。
4. 使用单个测试项目执行一次低成本文生和一次首帧图生冒烟测试。
5. 验证 R2 成片、历史列表与结果详情后再供日常使用。
